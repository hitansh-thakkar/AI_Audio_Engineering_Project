# Report 1 — Results of the best pipeline

_Generated by `python -m src.evaluation.suite.build_reports` from the benchmark outputs in

## The pipeline we recommend

Each stage was picked on measured evidence (see `report_comparison.md` for every alternative).

| Stage | Choice | Why | Cost |
|---|---|---|---|
| Preprocessing | {{preproc_choice}} | judged by its effect on downstream ASR, not by how the audio sounds | free, local |
| Diarization | ECAPA-TDNN embeddings + spectral clustering, speaker count estimated (eigengap) | lowest DER of every estimated-K system on sequential and mixture audio; finds 2 speakers on 23/24 code-switch clips where both pyannote systems find 1 | free, local (CPU) |
| Separation | SepFormer Libri2Mix, overlap regions only (diarization first) | 15.8 dB SI-SNRi on overlap regions vs 6.6 dB for the previous default (WSJ0-2mix) | free, local (GPU 0.85 GB) |
| ASR | **Sarvam** (measured best, external); **MMS-1B-all** is the best free/local system | Sarvam wins every one of 14 languages | Sarvam is a paid API (optional toggle); MMS free |
| LLM post-processing | Gemini 3.5 Flash-Lite (free tier) | most faithful dialogue cleaning (2.2% rewrite CER vs 11.4% for the best local model), 97% language labels, 0 invented numbers, fastest; Qwen2.5-Coder 7B is the offline alternative | free API |

Config changes made because of these results (`config/default.yaml`): `diarization.backend:
community1` (was the paid `precision2`), `diarization.embedding: ecapa` (was `auto`/MFCC), and
`separation.model: speechbrain/sepformer-libri2mix` (was `sepformer-wsj02mix`).

## Data

`dhvani_eval/` — all four proposal corpora as small slices: IndicVoices (260 clips), Nirantar
(260), Vaani (198, noisy crowd-sourced), plus 64 register clips (24 Hindi–English code-switch, 40
English) — 833 ASR clips in 15 languages, of which 782 are scored after excluding Sindhi (see
Methodology). Diarization uses 10 sequential multi-speaker clips, 24 synthetic two-speaker
mixtures and the 24 code-switch clips; separation uses the 24 mixtures (clean sources known).

## ASR — Sarvam (best measured system)

![Sarvam WER by language](charts/best_asr_wer_by_language.png)

Overall on 782 clips (Sindhi excluded): see the Sarvam row.

{{asr_overall}}

### WER per language

`sub`/`del`/`ins` are substitutions, deletions and insertions per reference word, so they sum to
WER. The last two columns name the strongest *other* system on the same clips, which shows there
is no language where another system wins.

{{asr_best_lang}}

The spread is driven by morphology and data, not by noise. Tamil, Telugu, Malayalam and Kannada
are agglutinative: one "word" carries what Hindi spreads over several, so a single wrong suffix
costs a whole word. Their CER (11–27%) is far lower than their WER, which is the signature of
near-miss word forms rather than of misheard speech. Tamil also has the highest insertion rate
(14.1%), from word-splitting of compounds the reference writes joined.

### By corpus and register

{{asr_best_corpus}}

{{asr_best_register}}

Vaani is the hardest corpus (39.1% WER) because it is spontaneous, noisy, phone-recorded speech.
The code-switch register has an unusually high CER (38.6%) relative to its WER: references write
English words in Devanagari, while ASR often writes them in Latin script, so every such word is a
full character-level mismatch. This is a transliteration-convention gap, not a hearing error; it
is why `normalize.py` records script share per clip.

## ASR — best free/local system (MMS-1B-all)

Sarvam is an external paid API, so it cannot be the default under golden rule 0. The best
system that runs on this PC for every language is MMS-1B-all (56.6% WER overall). The table shows
where another free system does better on the same clips.

{{asr_mms_lang}}

**Why not faster-whisper?** It is the proposal's best-known open ASR, but it is weak on Indic
languages other than Hindi and Urdu. Even after fixing a decoding bug on our side (a per-window
token cap that Indic scripts overflow), `large-v3` goes from {{fw_headline}}. It stays the better
choice only for English. Report 2, section 6 has the full evidence and the published baselines.

IndicWav2Vec-Hindi beats MMS on Hindi (36.9% vs 40.7%), so a Hindi-routed deployment should use
it for Hindi. MMS has no Sanskrit adapter; the Hindi adapter is used as a fallback, hence 93.7%.
On the 84-clip subset, Gemini 3.5 Flash-Lite (free API) scored 48.8% WER against MMS's 59.5%, but
the free tier allows too few requests a day to run the full set, so it is not a viable default.

## Diarization — ECAPA + spectral clustering

![DER components](charts/best_diar_components.png)

{{diar_best_components}}

DER is scored with `pyannote.metrics`, overlap included, no collar (the strictest setting). On
sequential and mixture audio the errors are balanced between missed speech and speaker confusion.
On code-switch clips nearly all error (45%) is *missed speech*, and that is a reference artefact:
46% of the reference speaker-time on those clips is silence by energy VAD, because the reference
turns span whole stitched clips, pauses included. Scored against VAD-tightened turns the same
output has 13.2% DER (`report_comparison.md`, Diarization).

## Separation — SepFormer Libri2Mix

{{sep_table}}

Separation runs only on regions diarization marks as overlapped. Libri2Mix was trained on read
LibriSpeech mixtures, which matches our read-speech material far better than WSJ0-2mix; it also
assigns separated streams to the correct speaker 75% of the time, the best of the four.

## LLM post-processing — Gemini 3.5 Flash-Lite

{{llm_best}}

There are no gold summaries, so every metric checks the output against the transcript it was
given (oracle reference text, to isolate the LLM). Rewrite CER 2.2% means the "cleaned" dialogue
stays faithful to what was said. 0.0 invented numbers per report. Document-level grounding: 73.5%
of summaries are closer to their own transcript than 95% of mismatched (summary, transcript)
pairs, and 67.6% retrieve their own transcript as the nearest of 34. The project guardrail's
5.9% pass rate is a guardrail bug, not a model failure — see `report_comparison.md`.

If the stage must run fully offline (the proposal's "localized" LLM), use Qwen2.5-Coder 7B via
Ollama. Its summaries are more specific: 82% are grounded and 79% retrieve their own transcript.
The cost is that it rewrites more of the dialogue (11.4% CER) and is 2.3× slower.

## Preprocessing

{{preproc}}

Every front-end was scored on the same 258 clips (all 198 Vaani clips, which are the noisy
ones, plus 60 seeded IndicVoices clips), using MMS-1B-all and the same normaliser. Level and filter
changes (peak, LUFS, a 70 Hz high-pass) all fall within ±0.25 pp of raw audio, which is noise
at this sample size. That is expected: MMS normalises each input to zero mean and unit variance,
so it cannot see loudness. Denoising hurts. `noisereduce` adds 8.7 pp WER, and 9.1 pp on noisy
Vaani, which is exactly where it was meant to help. The config therefore keeps `normalize: peak`,
`trim_silence: true` and `denoise: none`. Denoising the separated output tracks
(`denoise_output`) stays available for listening, but should not feed ASR.
